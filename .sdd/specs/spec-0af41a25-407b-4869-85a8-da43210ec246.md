# Technical Specification: Move Hashing and Equality to Native C++ Integers (GIL Elimination)

## 1. Overview
The goal is to eliminate Python GIL contention during MCTS tree traversal. Currently, `MCTS_node::advance_tree` compares children using `*(child->move) == *(m)`. For Python moves, this dispatches to Python's `__eq__` (or fallback `sprint()`), requiring the GIL on every comparison. By caching a native integer ID on the C++ side when the `PythonMoveWrapper` is constructed, we can perform fast integer comparisons during tree traversal, only falling back to `operator==` when integer IDs collide.

## 2. Interface Changes (`mcts/include/state.h`)
- Modify `struct MCTS_move` to expose a virtual method for retrieving the ID:
  ```cpp
  virtual uint64_t get_id() const { return 0; }
  ```
- **Rationale**: Returning `0` by default ensures existing pure-C++ moves (like those in `TicTacToe` or `Quoridor`) require no modifications. Since `0 == 0` evaluates to true, unmodified C++ moves will simply fall back to `operator==` as they always have, maintaining 100% backward compatibility.

## 3. Wrapper Enhancements (`pybind/py_wrappers.h`)
- Add a new cached integer ID member to `PythonMoveWrapper`:
  ```cpp
  uint64_t cached_id_;
  ```
- **Constructor Logic**: Inside `PythonMoveWrapper::PythonMoveWrapper(py::object py_move)`, compute and store the `cached_id_` exactly once (when the GIL is already held). The fallback chain must be:
  1. **Direct Attribute**: Attempt to retrieve an explicit `move_id` if defined on the Python object (`py_move.attr("move_id").cast<uint64_t>()`).
  2. **Python Hash**: Fall back to Python's native hashing: `static_cast<uint64_t>(py::hash(py_move))`.
  3. **String Hash**: As a last resort (for unhashable objects), compute a C++ string hash: `std::hash<std::string>{}(move_string)`.
- **Method Override**: Implement the virtual method to return the cached value.
  ```cpp
  uint64_t get_id() const override { return cached_id_; }
  ```
- **Safety**: This design is completely thread-safe. Construction happens sequentially while holding the GIL, and reads via `get_id()` are simple concurrent memory reads of the C++ member, requiring no Python interaction.

## 4. Traversal Optimization (`pybind/mcts_python.cpp`)
- In `MCTS_node::advance_tree`, update the linear scan over `children` (around line 219) to leverage short-circuit boolean evaluation:
  ```cpp
  for (auto *child: children) {
      if (child->move->get_id() == m->get_id() && *(child->move) == *(m)) {
          next = child;
      } else {
          delete child;
      }
  }
  ```
- **Performance**: The `$O(N)$` scan will now primarily execute fast CPU register comparisons (`uint64_t == uint64_t`). The slow `operator==` (which invokes the Python GIL) will only execute on integer matches (actual matches or hash collisions).

## 5. Cache Lookup Optimization (`pybind/py_wrappers.cpp`)
- In `SerializedPythonState::find_python_move`, apply the exact same short-circuit optimization to bypass the heavy `__eq__` on misses:
  ```cpp
  if (cached_cpp_move && cpp_move) {
      if (cached_cpp_move->get_id() == cpp_move->get_id() && *cached_cpp_move == *cpp_move) {
          return py_move;
      }
  }
  ```

## 6. Constraints & Scope
- **Pure-C++ Unaffected**: Do **not** modify `mcts/src/mcts.cpp`. The core C++ engine's `advance_tree` remains pure. This ensures that the GIL-bypass logic is confined strictly to the Python bindings (`pybind/` directory).
- **Data Structure Unchanged**: `children` must remain a `std::vector` (avoiding the allocation penalties of `std::unordered_map`), maximizing cache locality.
- **Uniqueness Check**: Hash collisions are safely resolved by the tie-breaking `operator==`, ensuring 100% logical correctness per state.
