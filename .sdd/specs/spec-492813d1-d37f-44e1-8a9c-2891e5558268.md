# Technical Specification: Fix Minimax Sign for Virtual Loss (TFT-233)

## 1. Overview
The current batched MCTS implementation always subtracts a hardcoded virtual loss of `1.0` from a node's score to repel search threads. In a Minimax tree, subtracting from the score of a node whose parent is a MIN node (opponent's turn) actually *increases* its attractiveness, causing thread pile-up. This specification outlines the changes required to dynamically flip the virtual loss sign based on the parent's turn and to make the virtual loss magnitude configurable.

## 2. Structural Changes

### 2.1 Configuration Properties
We will introduce a configurable `virtual_loss` property (default `1.0`) traversing from the Python API down to the `MCTS_tree`:

1. **`pybind/mcts_python.h`**:
   - In `class MCTS_tree`: 
     - Add `double virtual_loss;`
     - Add `void set_virtual_loss(double v) { virtual_loss = v; }`
     - Add `double get_virtual_loss() const { return virtual_loss; }`
   - In `class MCTS_agent`:
     - Add `void set_virtual_loss(double v) { tree->set_virtual_loss(v); }`
     - Add `double get_virtual_loss() const { return tree->get_virtual_loss(); }`

2. **`pybind/py_wrappers.h`**:
   - In `class SafeMCTS_agent`:
     - Add `void set_virtual_loss(double v) { agent->set_virtual_loss(v); }`
     - Add `double get_virtual_loss() const { return agent->get_virtual_loss(); }`

3. **`pybind/pymcts.cpp`**:
   - Expose the property in `py::class_<SafeMCTS_agent>`:
     ```cpp
     .def_property("virtual_loss", &SafeMCTS_agent::get_virtual_loss, &SafeMCTS_agent::set_virtual_loss, "Virtual loss applied during batched MCTS (default: 1.0)")
     ```

### 2.2 Updating Virtual Loss Methods
The methods `apply_virtual_loss` and `remove_virtual_loss` need to accept the magnitude as an argument and conditionally flip the sign depending on the parent's turn perspective.

1. **`pybind/mcts_python.h`**:
   - Update signatures in `class MCTS_node`:
     - `void apply_virtual_loss(double v);`
     - `void remove_virtual_loss(double v);`

2. **`pybind/mcts_python.cpp`**:
   - Initialize `virtual_loss(1.0)` in the `MCTS_tree::MCTS_tree` constructor.
   - Update `MCTS_node::apply_virtual_loss(double v)`:
     ```cpp
     void MCTS_node::apply_virtual_loss(double v) {
         MCTS_node* node = this;
         while (node != NULL) {
             node->number_of_simulations += 1;
             if (node->parent != NULL && !node->parent->state->is_self_side_turn()) {
                 node->score += v;
             } else {
                 node->score -= v;
             }
             node = node->parent;
         }
     }
     ```
   - Update `MCTS_node::remove_virtual_loss(double v)`:
     ```cpp
     void MCTS_node::remove_virtual_loss(double v) {
         MCTS_node* node = this;
         while (node != NULL) {
             node->number_of_simulations -= 1;
             if (node->parent != NULL && !node->parent->state->is_self_side_turn()) {
                 node->score -= v;
             } else {
                 node->score += v;
             }
             node = node->parent;
         }
     }
     ```
   - Update `SearchThreadPool::search_thread_func` to call `node->apply_virtual_loss(tree->get_virtual_loss());`.
   - Update `MCTS_tree::grow_tree` to call `node->remove_virtual_loss(this->get_virtual_loss());`.

## 3. Testing Strategy

1. **Test Hooks (`pybind/pymcts.cpp`)**:
   - Temporarily or permanently expose `apply_virtual_loss` and `remove_virtual_loss` in `py::class_<MCTS_node>` to enable unit testing the score modifications directly from Python.
     ```cpp
     .def("apply_virtual_loss", &MCTS_node::apply_virtual_loss, py::arg("v") = 1.0)
     .def("remove_virtual_loss", &MCTS_node::remove_virtual_loss, py::arg("v") = 1.0)
     ```

2. **Unit Tests (`tests/test_batched_mcts.py`)**:
   - **Minimax Repulsion Unit Test**: Create a small tree where a node's parent is a MIN node (`is_self_side_turn() == False`). Assert that calling `apply_virtual_loss(v)` increases the node's `score` by `v` and `visit_count` by 1. Call `remove_virtual_loss(v)` and assert the score returns to the original value.
   - **MAX Node Repulsion Unit Test**: Create a node with a MAX parent. Assert that `apply_virtual_loss(v)` decreases the score by `v`.
   - **Integration Test**: Verify `virtual_loss` can be configured on the `MCTS_agent` (e.g. `agent.virtual_loss = 2.0`). Run a batched MCTS search with `num_search_threads > 1` on an adversarial game (like TicTacToe) to ensure no deadlocks occur and the threads don't pile up erroneously.

## 4. Exceptions and Error Handling
- Root Node: The `apply_virtual_loss` logic inherently treats the root node (where `parent == NULL`) the same as a MAX node (`score -= v`). Since the root node is not selected via UCT, this score modification only affects `print_stats()` and does not impact selection behavior.
- Configuration defaults safely to 1.0, preserving identical magnitude behavior to the previous version but with correct signs.
